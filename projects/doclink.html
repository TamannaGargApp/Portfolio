The problem

Document collection is slow, scattered and hard to audit.

Service firms spend a lot of time chasing clients for documents over email, tracking what has arrived, and searching through files to answer questions. DocLink centralizes that work: firms create engagements, send organized document requests, review and approve submissions, and keep a full audit trail for compliance. Clients get a self-service portal to upload files and follow progress in real time.

My role

  • Supported large-file workflows up to 2 GB per file.

AI assistant

How the document chatbot answers questions

The assistant combines Retrieval-Augmented Generation (RAG) with a Context-Augmented Generation (CAG) layer. RAG finds the right passages in the firm's documents, and CAG keeps track of the conversation so follow-up questions like "which of them is high priority?" still make sense. Everything runs on local models, so client documents never leave the firm's infrastructure.

1 · Ingestion pipeline

  1. Upload stored in S3, metadata saved in MongoDB
  2. Text extracted from PDF, DOCX, XLSX, TXT and more
  3. Split into overlapping chunks with LangChain
  4. Embedded with all-MiniLM-L6-v2 (384 dimensions)
  5. Stored in Qdrant with firm, engagement and document IDs

2 · Understanding the question

  1. Conversation memory keeps the last few turns
  2. Query rewriting resolves "it", "this" and "they"
  3. Intent detected: search, summary, comparison, how-to…
  4. LLM intent classifier routes to database tools first
  5. Pattern matching, then RAG, as fallbacks

3 · Grounded answer

  1. Filtered vector search, always scoped to the firm
  2. Low-relevance chunks dropped by a score threshold
  3. Prompt built from document excerpts and conversation context
  4. Local Qwen LLM generates the answer
  5. Sources returned with document name and page

Private by design

Local Hugging Face models (Qwen and sentence-transformers) mean no external API calls and no per-request cost.

Tenant isolation

Every vector search is filtered by firm, so one firm's documents can never appear in another firm's answers.

Document-aware UI

A floating chat widget that works across an engagement or a single document, with clickable source citations.

Batch processing

Process a single document or every file in an engagement, and generate AI insights for the engagement.

Platform features

Engagement management

Create client engagements, track status from Pending to Completed, assign team members and manage due dates.

Document requests

Hierarchical categories, priority levels, approval workflows and comment threads on every request.

Client portal

Self-service dashboard where clients upload documents, track request status and download approved reports.

E-signature

Prepare documents for signing, then let clients or guests sign through a secure link.

Assessment hub

Create assessments, prepare them internally and collect client submissions with document annotations.

Reports

Generate reports, share them for client review and give external reviewers guest access.

Automation rules

Trigger-based actions for status changes and notifications across engagement workflows.

Super admin portal

Manage multiple firms from one dashboard, with cross-firm analytics and an act-as-admin mode.

Notifications & activity

Real-time notifications, a filterable activity timeline and comment badges with live refresh.

Security & compliance

Built for firms that handle sensitive client data.

Access is controlled by five roles (Super Admin, Admin, Manager, Staff and Client), and every important action is written to an audit log.

  • Two-factor authentication with TOTP
  • Account lockout after 5 failed logins
  • Session tokens validated on every request
  • Configurable inactivity timeout
  • Fresh login required for sensitive actions
  • scrypt / bcrypt password hashing
  • CSRF protection and HTTPOnly cookies
  • Comprehensive audit logging
