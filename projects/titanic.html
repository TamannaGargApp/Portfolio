TITANIC SURVIVAL

Predicting who survived with data preprocessing and machine learning

Given a passenger's class, sex, age, fare and family details, the model predicts whether they survived the Titanic disaster. The project covers the full workflow, from inspecting messy raw data to comparing three models, studying overfitting and saving the best one.

The problem

Real data is messy before it is useful.

The raw Kaggle file has missing ages, an almost empty Cabin column, text fields that carry no direct signal and categories a model can't read. Kaggle's test.csv has no Survived labels, so the cleaned train.csv is split 80/20 (712 training and 179 test passengers) to measure how well each model really performs.

What I did

  • Inspected the raw data and cleaned it into 7 numeric features with pandas.
  • Trained and compared Logistic Regression, a Decision Tree and a Random Forest, with 5-fold cross-validation.
  • Ran an overfitting experiment on tree depth and explained the result.
  • Saved the final Random Forest with joblib and added unsupervised K-Means clustering as a bonus.
  • Shipped it as a step-by-step Jupyter notebook and a runnable training script.

Workflow

From raw CSV to a saved model

1 · Clean the data

  1. Drop PassengerId, Name, Ticket and Cabin (Cabin is ~77% missing)
  2. Fill 177 missing ages with the median (28)
  3. Fill 2 missing ports with the most common one (Southampton)
  4. Encode Sex and Embarked as numbers

2 · Train & compare

  1. 80/20 train / test split with a fixed random seed
  2. Logistic Regression as the interpretable baseline
  3. Decision Tree (depth 3) readable as IF / ELSE rules
  4. Random Forest of 100 trees
  5. 5-fold cross-validation for a fairer comparison

3 · Final model & insights

  1. Random Forest scores highest and becomes the final model
  2. Confusion matrix to see where it makes mistakes
  3. Feature importance to see what drives predictions
  4. Model saved as a .joblib file for reuse

Results

What the models learned

All three models were trained and tested on the same split. With only 179 test passengers, one prediction moves accuracy by about 0.6%, which is why cross-validation was used alongside the single test score.

Overfitting experiment

A deeper tree memorises instead of learning.

As the Decision Tree is allowed to ask more questions, training accuracy climbs towards 98% while test accuracy stays around 80%. That widening gap is overfitting: the tree memorises the training passengers rather than learning patterns that generalise. A Random Forest reduces this by averaging many trees, each trained on a random sample of rows and columns.

Bonus · Unsupervised learning

K-Means clustering without the labels

Passengers were grouped by Age and Fare alone, without ever showing the model who survived. The groups it found still had clearly different survival rates.

Scaled first

Fare ranges from 0 to 512 and Age from 0 to 80, so both were standardised. Otherwise K-Means would group almost entirely by Fare.

Elbow plot

The inertia curve bends at K = 3, so passengers were split into three groups.

No label leakage

Clustering runs on a copy of the data, so the cluster column never leaks into the model features.

The finding

Higher-fare groups survived more often than lower-fare ones, even though the model never saw the Survived column.

What's next

Ideas to push the accuracy further.

The current pipeline is a clean baseline. These are the next experiments planned for it.

  • FamilySize feature from SibSp and Parch
  • Passenger title from Name (Mr, Mrs, Miss, Master)
  • One-hot encode Embarked
  • Tune the forest with GridSearchCV
  • Try Gradient Boosting and XGBoost
  • Predict test.csv and submit to Kaggle
