The idea

A magazine-style home for life and tech writing.

Life & Tech Journal brings personal growth and technology stories together in one editorial design. It is more than a static blog: readers have accounts, saved articles and a reading history, writers have their own publishing tools, and the whole site is managed through a CMS instead of code.

What I built

  • A Next.js 15 App Router frontend in TypeScript and Tailwind CSS with an editorial design system.
  • A FastAPI backend with Beanie ODM models on MongoDB and versioned /api/v1 routes.
  • JWT authentication in httpOnly cookies with token refresh, plus Google OAuth sign-in.
  • Role-based access for readers, authors and admins, and a CMS dashboard.
  • Redis caching, rate limiting and audit-logging middleware, S3 and CloudFront media, and Resend email.

How it's built

A typed frontend on a fast Python API

The Next.js frontend calls a FastAPI backend at /api/v1. The backend stores content in MongoDB, caches in Redis, serves images through S3 and CloudFront, and sends email through Resend.

1 · Frontend

  1. Next.js 15 App Router with TypeScript
  2. Tailwind CSS editorial design system
  3. Pages for home, blog, articles, profile, reading list and saved
  4. AuthProvider refreshes tokens automatically
  5. Admin CMS dashboard at /admin

2 · Backend API

  1. FastAPI on Uvicorn with interactive docs at /api/docs
  2. Pydantic schemas for every request and response
  3. Beanie ODM models on MongoDB
  4. Rate limiting and audit-logging middleware
  5. Settings loaded from a shared .env file

3 · Services

  1. Redis for caching
  2. AWS S3 for uploads, served through CloudFront
  3. Resend for transactional email
  4. Google OAuth for one-click sign-in
  5. bcrypt password hashing

Secure sessions

JWTs live in httpOnly cookies, out of reach of page scripts, and refresh tokens keep readers signed in.

Clean URLs

Articles are fetched by slug, so every story has a readable, shareable link.

Related reading
